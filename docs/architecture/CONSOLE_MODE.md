# Консольний режим INFO Desktop — проєкт (чернетка для рішення власника)

Статус: **пропозиція, код не написано**. Складено 05.11.2026 за вступним завданням власника. Фактичний стан коду перевірено в `src-tauri/src/lib.rs`, `registration.rs` і `scripts/check-static.mjs`.

## Навіщо
Щоб ті самі дії, які редактор робить у вікні, можна було виконувати командою: вручну в терміналі, зі скрипту й автоматично (наприклад, проєкт Б передає підготовлені дописи в чергу INFO). Ніякої нової логіки: сервер, як і раніше, головний, консоль лише інший спосіб викликати той самий протокол.

## Два режими роботи (вимога власника)
1. **Через відкритий застосунок.** Якщо вікно Десктопа запущене, консоль не відкриває власного з'єднання, а користується з'єднанням застосунку («вони діляться каналом»). Мережа, VPN і ключ уже налаштовані так, як працює вікно.
2. **Сама по собі.** Якщо вікна немає (наприклад, на сервері), консоль сама з'єднується з сервером INFO за ключем пристрою.

Консоль сама обирає режим: шукає запущений застосунок, інакше працює автономно. Можна примусити режим прапором `--mode app` або `--mode alone`.

## Як працює режим «через застосунок»
- Застосунок (якщо дозволено в налаштуваннях) відкриває **тільки локальний** вхід на цьому ж комп'ютері (не доступний з мережі) і записує у свою теку даних невеликий файл: порт і одноразовий випадковий пароль сеансу. Файл читається лише тим самим користувачем системи.
- Консоль читає файл, перевіряє, що застосунок живий, і передає команду з паролем сеансу. Застосунок виконує її своїм звичайним шляхом (з тими ж правами пристрою) і повертає результат.
- Ключ пристрою між застосунком і консоллю **не передається**.
- Застосунок показує в журналі, що консоль виконала команду; небезпечні дії (публікація, застосування налаштувань) можуть вимагати підтвердження у вікні.

## Як працює автономний режим
- Консоль бере профіль з'єднання (адреса, порт, номер пристрою, довірений сертифікат сервера) із файлу профілю (не секретний) і ключ пристрою.
- **Звідки ключ:** на комп'ютері з графічною системою — з того самого захищеного сховища ОС, що й у вікна (тоді це одне й те саме з'єднання пристрою). На сервері такого сховища немає: потрібен захищений файл ключа або передача через службу (див. «Рішення власника», пункт 1).
- Ніколи не виводиться в журнал, помилки й екран.

## Усі функції застосунку, які консоль має охопити
| Група | Команди | Права на сервері |
|---|---|---|
| Зв'язок | `status` (перевірка зв'язку й версії), `channels` | читання |
| Черга | `queue list`, `queue show ID` (матеріал із джерелами) | читання |
| **«Чому в цьому каналі»** | `why ID --channel КОД [--scope route\|auto\|digest\|instant\|relevance]` — пояснення, чому матеріал потрапив чи не потрапив у канал (дерево умов) | читання матеріалу |
| Редагування | `save`, `skip`, `defer`, `create` (вручну: канал, заголовок, текст, посилання) | запис, створення |
| Публікація | `publish ID` | окреме право публікації |
| **Налаштування через XLSX** | `settings status`, `settings download` (завантажити поточний XLSX), `settings check ФАЙЛ` (перевірка без застосування), `settings probe --hours N` («що зміниться за N год»), `settings apply` (застосувати перевірений), `settings rollback` | право налаштувань |
| Теми | `themes list`, `themes test`, `themes save` | право налаштувань |

Проєкт **не обмежується** Telegram: публікація в інші мережі (Facebook, TikTok тощо) буде реалізована на боці сервера INFO як нові адаптери каналів, а консоль просто створює й публікує матеріали в канал із відповідним кодом. Консоль від платформ не залежить.

## Запобіжники
- Усе, що змінює стан сервера (`publish`, `settings apply`, `settings rollback`, `queue skip` для багатьох), потребує явного прапора `--yes`; без нього лише «що було б зроблено» (`--dry-run` за замовчуванням).
- Вивід простий текстовий або `--json` для скриптів; коди завершення: 0 успіх, 1 помилка команди, 2 неправильні аргументи, 3 немає зв'язку/ключа, 4 сервер відмовив.
- Консоль не змінює VPN, мережу сервера, файрвол, SSH; не робить жодних тестових публікацій без команди.

## Що змінюється в коді (план малих кроків, кожен із перевіркою)
Локально на цьому комп'ютері немає Rust, тому збірка й тести — в GitHub Actions (чернетковий PR).
1. **Спільний транспорт.** Винести HTTP-виклики (`device_get`, `device_post`, `rotate`) з `lib.rs` у спільний модуль, щоб їх використовували і вікно, і консоль. Поведінка вікна не змінюється. Перевірка `scripts/check-static.mjs` зараз вимагає **рівно один** редакторський POST у `lib.rs` і **рівно два** виклики для ключів: її треба оновити, щоб вона вимагала те саме правило для всіх модулів, а не послаблювати.
2. **Каркас консолі** (окрема програма в тому ж проєкті) і команди читання в автономному режимі, з тестами розбору аргументів і форматів виводу.
3. **Команди запису** (`create`, `save`, `skip`, `defer`) із запобіжниками, тести проти імітації сервера.
4. **`why`, XLSX і теми** (завантаження, перевірка, проба, застосування, відкат).
5. **Режим «через застосунок»** (локальний вхід у вікні, файл сеансу, пароль, журнал, налаштування «дозволити консолі»).
6. **Автономний режим на сервері** — після рішення власника про зберігання ключа.
7. **Документація:** інструкція користувача, опис протоколу, оновлення README усіма 7 мовами (українська основна).
8. **Збірка й випуск:** консоль як окремі файли в релізі для Windows, Linux, macOS з контрольними сумами. **Випуск лише за окремим словом власника** і після приймання на Windows, як у правилах проєкту.

## Рішення власника (потрібні до коду)
1. **Ключ пристрою на сервері без графічної системи.** Варіанти: (а) захищений файл, доступний лише службовому користувачу; (б) передача через службу системи (наприклад, облікові дані служби); (в) на сервері лише режим «через застосунок» (тоді сервера без вікна не буде). Порада: (а) для початку, (б) пізніше. Це змінює правило «жодного відкритого тексту на диску» лише для цього режиму, тому потрібне ваше слово (правило 9 проєкту).
2. **Одне чи окреме з'єднання на ПК.** Порада: на вашому комп'ютері консоль користується тим самим пристроєм, що й вікно; на сервері окремий пристрій зі своїм ключем, який відкликається окремо.
3. **Вхід консолі у вікно (режим «через застосунок») за замовчуванням вимкнений** і вмикається галкою в налаштуваннях. Порада: так.
4. **Випуск:** консоль як окремі файли поруч зі встановлювачами. Порада: так.
