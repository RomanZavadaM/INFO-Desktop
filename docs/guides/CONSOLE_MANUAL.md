# Консольний режим INFO Desktop — коротка інструкція

Статус: випущено у складі 0.1.5. Є два режими: через відкрите вікно застосунку та автономний.

## Що це
Програма `info-desktop-cli` робить те саме, що вікно: показує чергу, пояснює маршрути, створює й редагує матеріали, публікує, працює з налаштуваннями XLSX. Ключ пристрою береться з того самого захищеного сховища системи, що й у вікна, і ніколи не виводиться.

## Режими
- **Через відкрите вікно (спільне з'єднання).** У вікні застосунку поставте галку «Дозволити консолі працювати через це вікно» (за замовчуванням вимкнена). Поки вікно відкрите, консоль користується його з'єднанням: VPN і ключ уже налаштовані, ключ нікуди не передається. Вхід відкрито лише на цьому комп'ютері (127.0.0.1) і захищено одноразовим паролем сеансу, який лежить у теці налаштувань користувача. Кожну дію консолі вікно показує поруч із галкою.
- **Автономно.** Вікно не потрібне: консоль сама з'єднується із сервером за профілем з'єднання й ключем зі сховища ОС. Профіль вікно записує саме при кожному підключенні (адреса, порт, номер пристрою, сертифікат сервера; без ключів); за потреби його можна задати вручну (`profile set`).
- Вибір: `--mode auto` (за замовчуванням: вікно, якщо воно відкрите й дозволило консоль, інакше автономно), `--mode app` (лише через вікно), `--mode alone` (лише автономно). Явний `--profile` без `--mode` означає автономний режим.

## Перший запуск
1. У вікні застосунку підключіться до сервера як завжди (на Windows під час роботи з нашим сервером має бути ввімкнено VPN).
2. Профіль з'єднання вікно запише саме. Лише якщо потрібно задати вручну (наприклад, без вікна):
   `info-desktop-cli profile set --server АДРЕСА --port ПОРТ --device-id НОМЕР --ca-file ФАЙЛ`
   Файл містить значення `server_ca_der` з реєстраційного файлу.
3. Перевірте зв'язок: `info-desktop-cli status`.

## Команди
Повний перелік: `info-desktop-cli` без аргументів покаже довідку.

| Що зробити | Команда |
|---|---|
| Список каналів | `channels` |
| Черга | `queue list [--limit N] [--cursor N] [--channel КОД] [--bucket ГРУПА]` |
| Матеріал з джерелами | `queue show НОМЕР` |
| Чому матеріал у цьому каналі | `why НОМЕР --channel КОД [--scope route\|auto\|digest\|instant\|relevance]` |
| Створити матеріал | `create --channel КОД --title ТЕКСТ (--text ТЕКСТ \| --text-file ФАЙЛ) [--url АДРЕСА]` |
| Змінити матеріал | `save НОМЕР --title ТЕКСТ (--text ТЕКСТ \| --text-file ФАЙЛ) [--channel КОД]` |
| Пропустити, відкласти, опублікувати | `skip НОМЕР`, `defer НОМЕР [--minutes N]`, `publish НОМЕР` |
| Налаштування XLSX | `settings status`, `settings download --out ФАЙЛ`, `settings check ФАЙЛ`, `settings probe [--hours N]`, `settings probe-status`, `settings apply [--without-probe] [--yes]`, `settings rollback [--yes]` |
| Теми й слова | `themes list`, `themes test ...`, `themes save ...` |

## Як зі зміною налаштувань
Спершу `settings check` (перевірка файлу без застосування), потім `settings probe` і `settings probe-status` («що зміниться»), потім `settings apply`. Без `--yes` команда лише показує, що було б застосовано. Застосовується рівно той файл, який перевірено (за відбитком). Без проби застосування відмовляє, якщо не додати `--without-probe`. Відкат: `settings rollback --yes`.

Публікація (`publish`) і звичайні редакторські дії підтверджень не потребують: на розсуд і відповідальність виконавця; допис завжди можна видалити в каналі.

## Коди завершення
0 успіх, 1 помилка команди, 2 неправильні аргументи, 3 немає зв'язку або ключа, 4 сервер відмовив (немає прав, конфлікт).

## Що ще не зроблено
Робота на сервері без графічної системи (відкладено власником), складання консолі в пакети випуску, повна документація 7 мовами. Перевірено на Windows 05.11.2026 із справжнім сервером (читання): `status`, `channels`, `queue list`, `why` через вікно, `status` автономно й автоматично. Не перевірено: команди запису, XLSX і теми, macOS і Linux.
