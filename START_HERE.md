## Startup protocol

Перед змінами:
1. Прочитати цей файл.
2. Прочитати `PROJECT_RULES.md`.
3. Прочитати `PROJECT_STATE.md`.
4. Прочитати `WORKLOG.md`.
5. Перевірити фактичний GitHub: main SHA, активну гілку/PR, CI, releases.
6. Продовжити з першого незавершеного `DOING/NEXT`.

GitHub має пріоритет над пам'яттю чату.

## Продукт

INFO Desktop — окремий універсальний desktop-клієнт для INFO-сумісних серверів.

Поточна робоча гілка:
`prototype/read-only-client`

Поточний етап:
`0.1.0-dev — read-only newsroom`

## Незмінні межі першого етапу

- Читати **реальні** дані сервера, а не тестову вигадану чергу.
- Не змінювати серверний стан.
- Не мати прямого доступу до SQLite.
- Не використовувати SSH як робочий протокол клієнта.
- Не містити production-секретів у репозиторії або збірках.
- Не чіпати чинний Telegram-функціонал.
- Не змінювати приватний `RomanZavadaM/INFO`, поки конкретна потреба протоколу не буде сформульована й погоджена.

## Перша контрольна точка

Desktop підключається до реального INFO-compatible server та швидко показує:
- стан сервера;
- канали;
- реальну pending-чергу;
- картку матеріалу;
- текст;
- медіа;
- оцінки/статуси;
- пов'язані матеріали, якщо сервер їх віддає.

Жодних write actions.
